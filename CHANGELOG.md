# Changelog

## Unreleased

- Add real Docker isolation probes (`tests/integration/test_docker_isolation_real.py`). The existing Docker tests only showed that a command runs in a container. These run probes inside it with the real daemon: loopback-only network, read-only root mount flag with writable `/tmp` and workspace, every capability set empty and no new privileges, non-root user, no host secrets or Docker socket, no host path mounted except the workspace and the daemon's own `/etc` files, CPU quota, pids limit against a fork bomb, memory limit ending in an OOM kill, and a timed-out container killed and removed. Controls with the protection absent show each probe can fail, using a non-root user like CI. Each option was removed or loosened in the runner in turn and a probe failed when run as a non-root caller. CI now requires all 15 to run with no skips. The sandbox still runs as the calling user, so it is not root-safe by itself, and container escape resistance is still not certified.
- Add `decisionbound.worker_child`, a real child entrypoint for the offline `prepare` kind, and `dbound workflow serve --contained`. Preparation can now run in a child process that is killed at its deadline and on cancel, and that the next coordinator kills after a coordinator crash, instead of in an unkillable thread. Without strong containment every task is refused and blocked, and the command stops if the child cannot import the package. The host still recomputes the capsule, so a forged digest is blocked (checked by mutation). Coding repair is not moved into a child. Tested with real processes in `tests/integration/test_worker_child_prepare.py`.
- Add a draft CarryBench annotation guide v1.2 (`benchmarks/carrybench/real_v1/guides/guide_v1_2.md`). It proposes rules for five ambiguities reported by the two blind annotators on the v2 holdout (mixed spans, practice versus availability scope, language conditions, same position on a different channel, path-only pointers) and one pitfall noted by annotator A (a nearby line that reverses the pinned one) and lists changes for building the next set. It has not labelled any case.
- Fix `database is locked` under slow disks. SQLite's busy handler is not fair, so with several writer threads one could lose the race for longer than the busy timeout, which failed the bounded state stress step on a Windows runner. `SQLiteRepository` now queues threads of one process per database file in arrival order and keeps SQLite's busy timeout for contention between processes (`busy_timeout_seconds`, default 10, and `queue_patience`, default 3 times that for threads waiting in the queue). A waiter whose turn does not come within that limit still gets `database is locked`, so a holder that never releases cannot hang anyone. Writers wait in that queue and so can wait up to 30 seconds instead of about 10. The repository's own pure read methods skip the queue, because under WAL a read does not wait for a writer. Reads made elsewhere through `_connection()` still queue. Reproduced locally with 60 ms commits before the fix and covered by `tests/unit/test_storage_fair_lock.py`. Repeated on real Windows Server 2022 and 2025 runners, where the old code failed some heavy stress runs with `database is locked` and the version before the read-skips-queue change failed none of 40 (details and limits in PR 14).
- Make two timing-dependent tests check their real property. The supervisor stress test now forces overlap with an event instead of hoping 12 ms sleeps overlap, and the keyset rotation test runs until every workflow is served instead of for a fixed two seconds. Both failed under simulated slow commits before this change.

- Make the real VS Code host gate depend on our own evidence. `apps/vscode/test/host/runner.cjs` now prints `DBOUND_HOST_RUNNER_EXIT code=<n>` and exits non-zero on a non-zero code, and both workflows require `code=0` and forbid any other value. The gate used to rely on a line VS Code prints itself, which appears only under some environments, so it could not be reproduced outside CI. Checked against a real Extension Development Host under xvfb. A real host failure makes runTests throw, so it is caught by the catch block, the existing forbid on the failure text and the missing markers. The non-zero `code=<n>` branch is defensive and was exercised with a hand-written log.
- Added CarryBench-Real v2 holdout: 40 candidates committed unlabelled, labels frozen from two blind AI annotators (35 agreed cases, 5 contested and excluded), then baselines and the shipped DecisionBound policy scored once with unchanged code. Results are in `benchmarks/carrybench/real_v2_holdout/HOLDOUT_RESULTS.md`. The shipped policy again equals always abstain by default, and the earlier claim that no setting scores above 0.41 no longer holds.

- Rewrite the README around one 60-second offline demo (three projects, one approved decision, `apply`, `translate` and `abstain` outcomes, then a context capsule) with real output pasted from a run, an install that uses `pip install .`, and a plain status section that links CarryBench and says its labels are LLM-made with no human labels. The Pages quickstart now carries the same demo, a correct clone URL, and notes on confusing output (`approve` returns revision 2, `write_consent: false` is informational). Fix stale statements in the docs index, SDK page and `src/decisionbound/README.md`.
- Add `tests/integration/test_docs_quickstart.py`: runs the README and Pages demo from the installed package and compares output with the documented blocks, checks that every `dbound` command and option in the docs exists, that documented pip extras exist, that README links resolve, that the example scripts and workflow manifests run, and runs the SDK example.
- Add CarryBench-Real v1 under `benchmarks/carrybench/`: 66 real cases from 50 permissively licensed repositories as pinned pointers and hashes (no third-party text), labelled by two blind LLM annotators with no human labels, with a dataset card, agreement report, eight simple baselines, scores for the shipped transfer methods, two guide-free language model runs, 33 executable end-state checks on synthetic reductions, and fetch, mine, verify and scoring tools. The set is unvalidated and small, and every document says so.
- Fix the package `__version__` (it said 0.6.0a1) and add a test that keeps it equal to `pyproject.toml` and `CITATION.cff`.
- Add a README section on closely related decision-memory work, and say plainly that the bundled fixtures are synthetic.
- Add worker-process containment (`decisionbound.containment`): `ContainedWorker` runs tasks in a killable process tree with a hard deadline, an allowlisted environment, bounded single-line receipts and optional resource limits. The containment tests pass in CI on Linux, macOS and Windows (Python 3.11 to 3.13). Open review items remain for Windows, listed in the containment page.
- Add `ProcessRegistry`, a lazy additive `contained_processes` table (schema version stays 2), and `OrphanReaper`, which kills only processes whose start token matches.
- The supervisor now creates an `ExecutionControl` per lease, ticks every `min(0.5, lease/3)` seconds, cancels workers on a revoked claim, stop grace expiry or lost leadership, and records `late_result_rejected` events. `WorkflowWorker.execute_controlled` defaults to `execute`, so existing thread workers behave as before.
- The coordinator reaps orphans right after acquiring leadership and reports `orphans_reaped` and `orphans_unconfirmed`. New setting `worker_stop_grace_seconds`. New command `dbound workflow reap-orphans`.
- New quarantine reason `containment_failed` and journal helpers `note_late_result`, `record_containment_event`, `block_uncontained` and `claim_is_current`.
- Gate G17 is partially met, not closed.

## 0.13.0a1 — experimental alpha

Platform, isolation and security limitations are documented in the user guides and SECURITY.md. No stable release or production certification is claimed.
